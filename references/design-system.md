# 微信安全设计系统

所有 token 是排版决策的起点，不是每篇都要原样使用。文章正文必须使用内联样式；硬约束以 [wechat-html-spec.md](wechat-html-spec.md) 为准。

## 共通版式

| 层级 | 建议 |
|---|---|
| 正文 | 14–16px，line-height 1.75–1.9，`text-align:justify` 仅用于连续中文段落 |
| 大节标题 | 17–19px，700–900，前方留 40–52px 空白 |
| 次级标题 | 15–16px，700–800 |
| 标签/图注 | 10–12px，600–700，适度字距 |
| 容器 | 单列，左右 20px 左右留白，`max-width:677px` |
| 圆角 | 8–16px；同篇使用 1–2 个尺度 |
| 阴影 | 仅轻微分层；纯文字区不用阴影 |

用 `margin-right` / `margin-bottom` 保证 flex 子项间距，不将 `gap` 作为必要布局。避免 position、transform、动画和横向滚动。

## 色彩纪律

1. 选择一套中性基底与一个主强调色；一篇中关键动作/概念只用主色。
2. 辅助色只传达语义：绿色=确认/进展，琥珀=注意，红色=真实风险，蓝色=信息。不要把它们当装饰彩虹。
3. 正文与背景必须保持清晰对比；浅色字只放在足够深的色块中。
4. 深色块是节奏点，不是默认背景；全篇通常不超过 3 个。

## 组件密度

- 纯观点文章：以段落、引文、细分隔和留白为主，卡片是例外。
- 教程文章：步骤和代码卡可重复，但每段说明仍应有呼吸感。
- 数据文章：用少数可信 SVG 图代替一串小卡；图下写结论，不让读者自己猜。
- 新闻/信号文章：视觉标记证据等级，严禁用强视觉暗示未证实事实。

## 可读性与编辑器可靠性

- 重要内容不要只用颜色传达；同时使用文字标签、图形或位置。
- 图片加 `display:block;width:100%;`，必要时加保守圆角；不要依赖固定高度裁切。
- SVG 用简单图元、显式颜色、`font-family="system-ui"`；不要嵌动画、外部字体、滤镜或交互。
- 用语义标签（`p`、`section`、`blockquote`、`ul`）和简短结构，便于微信编辑器保留。
